Microsoft Foundry: Production Agent Architecture at Enterprise Scale
Microsoft's Marco Casalaina (VP Core AI) details why production agents fail — not because of the model, but because of the harness: context retrieval, identity layer, guardrails, evaluators, and observability. Key architectural signals: retrieval-as-a-subagent (planner-driven, multi-source, retry-capable), agents assigned their own identities with audit trails, and rubric-based evals with auto-improvement loops. When Anthropic released Claude Opus 4.8, GitHub Copilot CLI had to re-tune its harness and re-run all evaluations before shipping — models are not like database versions.

CISA Publishes Postmortem on 6-Month GitHub Credential Leak — AWS GovCloud Keys Exposed
A contractor published a public GitHub repo ('Private CISA') containing 844 MB of sensitive data including AWS GovCloud admin keys and a plaintext CSV of internal system credentials; it sat exposed for ~6 months. CISA ignored nine automated GitGuardian alerts before KrebsOnSecurity notified them directly, then took 48+ hours to rotate the AWS keys. The official postmortem — the first time a national cybersecurity agency has publicly advocated for continuous secrets scanning — cites lack of distinct internal vs. external incident reporting channels and no GitHub/cloud-services playbook as root causes.

GitGuardian Analysis: Nine Ignored Alerts and the Case for Continuous Secrets Scanning
GitGuardian's Guillaume Valadon notes the core failure mode: automated secret-scanning alerts treated as noise, allowing a one-day incident to become a six-month exposure. His recommendation is continuous (not quarterly) scanning of public repos, internal scanning to catch secrets before they leave the perimeter, and distinct inbound reporting channels for infrastructure incidents separate from product vulnerability disclosures. CISA's zero-trust logging posture did allow post-hoc confirmation that no credentials were used outside its environments.

Microsoft Foundry's Agent Identity Pattern: Non-Human Identities with Org-Recognized Audit Trails
A recurring production failure mode in enterprise agents is running as a shared system principal with no audit trail — creating compliance and forensics gaps. Microsoft Foundry's pattern assigns each agent its own identity recognized by the organization, enabling action-level audit trails that survive compliance review. This directly mirrors IAM best practices for non-human identities (service accounts, workload identity) applied to agentic systems.
