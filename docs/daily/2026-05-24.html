RAG vs Agentic Architecture: Decision Framework and Trade-offs
RAG is appropriate when answers live in documents — single retrieval, single generation, cheap and debuggable. Agents are for tasks requiring action on external systems: they run a reasoning loop, select tools, execute, and iterate until the goal is met. The cost is more tokens and compounding error drift across steps.

Claude Code Context Management: 5-Layer Lazy Degradation Strategy
Before every model call, Claude Code runs up to five context-management strategies in escalating order of disruption: budget reduction (cap tool outputs), snip (trim oldest history), microcompact (prune tool turns by ID to preserve prompt cache), context collapse (read-time projection), and auto-compact (full model-generated summary as last resort). The architecture is instructive for anyone building long-running agentic sessions — prioritise cache warmth and avoid full summarisation until necessary.

Forward Proxy vs Reverse Proxy vs API Gateway: Architectural Boundaries
Forward proxy represents the client (outbound policy enforcement, IP masking); reverse proxy represents the server (TLS termination, load distribution, backend shielding); API gateway is a reverse proxy augmented with auth, rate limiting, versioning, and request shaping applied consistently across microservices. In production, all three layers typically coexist — relevant to IAM/zero-trust architectures where policy enforcement points must be clearly separated.
