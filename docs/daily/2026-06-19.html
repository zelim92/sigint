27-Year-Old OpenBSD PAP Auth Bypass: Zero-Credential PPPoE Authentication via sppp(4)
A 1999-era bug in OpenBSD's sppp_pap_input() allowed a PPPoE peer to authenticate with name_len=0/passwd_len=0, causing bcmp to return 0 and granting full auth with no credentials; oversized lengths triggered a kernel heap over-read. Reachable unauthenticated from the same broadcast domain (pppoe_data_input chain), patched June 14 (openbsd/src@076e2b1) — admins on sppp(4) PPPoE links should rebuild immediately.
